Operator guide · v1

Move a legacy Angular component into a measurable stress lab.

This guide takes a new contributor from an empty migration workspace to a faithful Storybook target tested at up to 100,000 items. OpenCode agents own one stage at a time; the human operator approves inputs, checks evidence, and starts the next stage.

11ordered migration stages
1×generator run per target
100kmaximum stress dataset

Before touching code

The migration is a pipeline, not a rewrite.

Inspect›Plan›Scaffold root›Adapt leaves first›Data›Harness›Test›Compare›Repair

Human responsibility

  • Provide component name and read-only legacy path.
  • Invoke one primary agent at a time.
  • Review each handoff before starting the next stage.
  • Supply missing assets, routes, or acceptance authority.

Agent responsibility

  • Load only current-stage context.
  • Use narrow subagents when their specialty is needed.
  • Validate outputs and record evidence.
  • Update state, write handoff, then stop.

Non-negotiable

Golden rules

Legacy stays read-onlyNever edit production source, data, or configuration.
Discover top-downStart at root template and recursively map rendered children.
Implement bottom-upFinish and compile leaves before parents. Root UI comes last.
Generate onceRun generator only for top-level benchmark target—never children.
Fidelity firstPreserve DOM, classes, Less, interactions, and local UI state.
No guessingMissing source or unclear business logic means blocked, not invented.

Part 1

Set up the environment

Do this once per workstation.Install Node.js, npm, OpenCode, and a Chromium browser supported by Playwright. Clone this repository and install dependencies.
npm install
npx playwright install chromium
npm run build-storybook

Connect the legacy application

Keep the legacy repository beside this repository or at another stable path. Confirm you can read its component, template, styles, assets, package manifest, and global theme files. Do not copy the entire application into StoryBook-Test.

Bootstrap before the first component from a new application.Run Project Bootstrap when dependencies, themes, fonts, global Less, or shared primitives have not yet been prepared for that legacy application.

Part 2

Use the agents in OpenCode

Start OpenCode from repository root. Project agents are auto-discovered from .opencode/agents/. Primary agents appear by stage name; nested subagents use IDs such as source-analysis/component-tree-analyzer.

Primary agents

Switch with OpenCode’s agent selector or Tab shortcut. Choose the stage you need, then give it component name and required source path.

Use the Source Analysis Agent for customer-page. Legacy source: ../legacy-app/src/app/customer-page

Subagents

Main agents select them automatically. You can also mention one explicitly for a narrow inspection, for example @source-analysis/style-dependency-analyzer.

Do not ask a subagent to run a full migration stage. Main agents own integration, state, validation, and handoffs.

OpenCode agent definitions follow the official project convention and preserve the canonical bodies in .agents/. Regenerate mirrors after canonical prompt changes:

node scripts/generate-opencode-agents.mjs

Evidence trail

Know the migration workspace

Every target gets one resumable workspace. Read state.json and latest handoff before invoking a stage.

.migrations/<component>/ ├── state.json ├── source/source-files.json ├── analysis/ # tree, dependencies, summary ├── plan/ # boundary, data contract, file plan ├── logs/ # copies and meaningful decisions ├── validation/ # builds, parity, evidence └── handoffs/ # one factual handoff per stage
Handoffs are gates.A completed file is not enough. Proceed only when state and handoff both say the stage passed its Definition of Done.

Part 3

Run the 11 stages

Replace [ component-name ] with the top-level benchmark target, select the matching primary agent, and send the prompt shown on its card.

Environment

Project Bootstrap

Prepare presentational dependencies, global Less, theme tokens, fonts, assets, and shared UI primitives.

  • Run once for a new legacy app or global-theme change.
  • Confirm Angular and Storybook builds.
  • Does not migrate a target component.
Prompt to send
Prepare the repository environment for migrating [ component-name ] from the legacy application. Run the Project Bootstrap stage, update its migration state and handoff, validate the build, and stop when this stage's Definition of Done is met.
Read-only

Source Analysis

Map the complete rendered tree from parent to leaves and classify every dependency.

  • Input: root component path.
  • Output: tree, dependency inventories, risks.
  • Stop if a rendered child cannot be resolved.
Prompt to send
Analyze [ component-name ] using the Source Analysis stage. Discover its complete rendered component tree top-down, inventory all dependencies, update migration state and handoff, and stop when this stage's Definition of Done is met.
Blueprint

Migration Planning

Define dumb boundary, post-order sequence, shared reuse, data contract, and exact file operations.

  • Every child precedes its parent.
  • Every smart dependency gets a treatment.
  • No code migration yet.
Prompt to send
Create the migration plan for [ component-name ] using the completed Source Analysis artifacts. Define the presentational boundary, strict post-order sequence, dependency treatments, data contract, file operations, state, and handoff. Stop when the Migration Planning Definition of Done is met.
One command

Component Scaffold

Create the benchmark root and registry entry with the repository generator.

npm run generate:component [ component-name ]
  • Run exactly once.
  • Never run for child components.
Prompt to send
Scaffold [ component-name ] using the Component Scaffold stage. Run the repository generator exactly once for the top-level target, verify its folders and registry entry, update migration state and handoff, and stop when this stage's Definition of Done is met.
Core migration

Component Tree Migration

Copy and adapt one node at a time in strict post-order.

  • Preserve DOM, classes, Less, local UI state.
  • Convert store/service/router/env boundaries.
  • Angular-template compile each node before parent.
  • Migrate root UI last.
Prompt to send
Migrate the UI tree for [ component-name ] using the approved plan. Work one node at a time in strict post-order, validate every node before its parent, preserve source fidelity, update migration state and handoff, and stop when the Component Tree Migration Definition of Done is met.
Deterministic

Data

Build TypeScript models, Zod schemas, seeded factories, and baseline/edge/stress datasets.

  • Default: 10–50 items.
  • Stress: 1k, 10k, 100k.
  • Validate every generated shape.
Prompt to send
Implement deterministic benchmark data for [ component-name ] from the approved data contract. Add models, Zod schemas, seeded factories, default, edge, 1k, 10k, and 100k datasets; validate every shape; update state and handoff; then stop at the Data stage Definition of Done.
Lifecycle

Harness

Wire the UI to the benchmark container and create CSF3 stories.

  • Extend BaseBenchmarkContainerComponent<T>.
  • Preserve ready/busy, race guards, size events, double rAF.
  • Use fullscreen stories and tracked interactions.
Prompt to send
Create the benchmark harness and Storybook stories for [ component-name ]. Preserve the shared readiness, race, sizing, error, and double-requestAnimationFrame contract; wire tracked interactions; validate; update state and handoff; and stop at the Harness Definition of Done.
Registry

Benchmark Integration

Verify registry metadata, performance tracker, paint events, size propagation, and runner compatibility.

  • Does not create stories.
  • Confirms existing harness integration.
Prompt to send
Integrate [ component-name ] with the benchmark runtime. Verify registry metadata, performance tracking, paint-cycle events, size propagation, and runner compatibility; update migration state and handoff; and stop when the Benchmark Integration Definition of Done is met.
Browser test

Test

Create deterministic Playwright scenarios and capture FPS, heap, DOM, layout, and runtime failures.

  • Wait for data-ready="true".
  • No fixed sleeps.
  • Keep workers: 1.
Prompt to send
Create and run the single-worker Playwright benchmark scenarios for [ component-name ]. Cover deterministic interactions and stress sizes, collect CDP performance metrics, capture runtime failures, update state and handoff, and stop when the Test stage Definition of Done is met.
Evidence

Fidelity Validation

Compare matching legacy and Storybook states across visuals, DOM, styles, behavior, and themes.

  • Stable finding IDs.
  • Severity and lowercase status for every deviation.
  • Accepted differences need an explicit decision.
Prompt to send
Validate fidelity for [ component-name ] by comparing matching legacy and Storybook states. Check visuals, normalized DOM, computed styles, interactions, and theme tokens; record evidence-backed findings; update state and handoff; and stop at this stage's Definition of Done.
Only if needed

Repair

Fix one reported failure with the smallest evidence-backed change.

  • Reproduce narrow failure first.
  • Run full affected-stage validation after fix.
  • No broad cleanup or redesign.
Prompt to send
Repair [ component-name ] using the unresolved finding in its latest validation report. Reproduce the narrow failure, apply the smallest evidence-backed fix, rerun the affected validation, update the finding, state, and handoff, and stop when the Repair Definition of Done is met.

Interrupted work

Resume safely

  1. Open .migrations/<component>/state.json.
  2. Read currentStage, status, warnings, and latest matching handoff.
  3. If in_progress or failed, invoke the same primary agent.
  4. If blocked, supply the exact missing prerequisite first.
  5. Never skip forward because target files happen to exist.

When something fails

Diagnose smallest scope first

Unknown selector or input

Confirm child migrated first, standalone import exists, selector matches source, and parent did not jump ahead.

Injector/provider failure

Keep presentation providers. Convert application data/control/environment dependencies at planned boundary.

Story stays busy

Inspect generator errors, stale request guards, size event, and double-rAF completion. Do not add arbitrary waits.

Playwright timeout

Check page errors and data-ready first. Prefer semantic locators. Keep one worker.

Less variable missing

Trace source token, include path, casing, and theme import. Do not approximate the value.

100k memory growth

Repeat fixed-seed runs; inspect retained heap, DOM nodes, listeners, timers, detached nodes, and lifecycle cleanup.
